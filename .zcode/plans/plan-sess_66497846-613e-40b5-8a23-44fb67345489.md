# 《崩老头》游戏规划（女性视角 · 严肃现实向 · 复用华丽人生2架构）

## 一、游戏概念（不变）

你是一个经济压力下的年轻女性，深夜用手机同时维系着几个孤独的中年男人——体验"崩老头"这门灰色生意的全部：话术、时机、精力、麻木，以及账单背后那些真实的人。基调严肃现实：老头们是真实孤独的人，主角没有纯爽线，游戏始终在记录代价（精力、麻木、良心、风险）。开场带内容提示；话术内容停留在游戏抽象层，不写成可实操的诈骗教程。

## 二、从《华丽人生2》参考的设定（本次核心增量）

我已通读 GorgeousLife2 的代码（React 19 + Zustand + TS + Vite，约 1.16 万行，纯函数引擎 + 数据驱动内容层）。**技术栈改为与华丽人生2完全一致**（原计划的"原生 DOM"方案作废），并移植以下经过验证的设定：

| 华丽人生2 的设定 | 崩老头中的对应物 |
|---|---|
| **女友静态卡 + 运行时状态分离**（`Girlfriend` 定义 / `GirlfriendState` 状态） | 老头卡：静态定义（原型/小传/喜恶/话题偏好/警惕阈值/付费习惯）+ 运行时状态（信任/警惕/依赖/断联天数/阶段） |
| **6 类型匹配系统**（类型对互动 ×2，错配 ×0.3，`typeColors/typeIcons` 视觉标签） | **4 人设卡 × 老头偏好匹配**：清纯学妹对"想找女儿感觉"的老头 ×2，对"想证明魅力"的老头 ×0.3——人设选择即策略 |
| **love/fatigue/endurance 三轴 + 每回合衰减**（love-1/疲劳-5/needs_attention +25） | 信任(0-100)自然衰减、警惕(0-100)要到红包后上升后缓慢回落、"需要关注"型老头断联惩罚加倍 |
| **trait 枚举作为引擎钩子**（fatigue_halved/loyal 等 5 种） | 老头 trait：夜猫子（只深夜在线）/阔绰（红包大）/疑心重（警惕衰减慢）/孤独成瘾（要钱易）/粘人（断联信任掉得快） |
| **19 场景台词矩阵 + seed 确定性选取**（pickLine，同状态同台词、可重放） | 老头原型 × 场景矩阵（开场问候/聊爱好/低落倾诉/多疑试探/红包到手/要钱被拒/深夜/清晨/被拉黑…），同 seed 重放一致 |
| **醋意波软上限**（囤 40 女友收入≈8 个全薪） | **人设穿帮机制**：同时经营多个老头会积累"朋友圈穿帮风险"，集体警惕上升——多线经营的规模惩罚，逼玩家取舍 |
| **一次性/可重复事件表**（3d6 查表 + oneTime 标记，纯数据 Effect） | 日结算掷骰事件：日常小波动可重复（他加了你又删、股票跌了心情差），高影响剧情一次性（视频通话危机、约见面、太太查岗、产业化招募） |
| **纯函数 dispatch 引擎 + EventLog 叙事总线 + Zustand 薄封装（76 行）** | 直接沿用：`dispatch(state, action)` 类型化判别联合；事件日志（含聊天流）作为 UI 演出唯一事实源 |
| **程序化 SVG 立绘**（PortraitSpec 数据驱动、立绘头像同源、随数值变表情、gallery.html 对照工具） | 零美术成本老头头像：发际线/胡子/眼镜/发福脸型参数化，表情由信任/警惕实时驱动（警惕高→眯眼审视）；主角人设外观同理 |
| **Web Audio 合成音效**（骰子/金币/邂逅心跳，零音频文件） | 消息提示音、红包到账（改编金币双音阶）、拉黑警报、深夜氛围低频 |
| **fxQueue 串行演出队列 + 优先级** | 聊天消息逐条打字机节奏、红包弹窗、危机横幅、结局演出按优先级排队 |
| **constants.ts 平衡常量带设计注释 + balance/simulation/safeguards 三类测试**（AI 自动跑局验证不变量） | 崩老头数值全部集中在带注释的 constants.ts；simulation 测试让 AI 自动玩局验证（信任∈[0,100]、月收支不穿模）；**safeguards 测试断言：所有老头目标均为中年+、无未成年人、文案不含可实操诈骗话术细节** |
| **seed RNG（mulberry32）+ 可序列化 JSON 状态** | 直接沿用，并补上 GL2 缺失的存档系统（localStorage 序列化 state） |
| **胜利者女友画廊结局演出** | **账本回顾结局画廊**：每个老头的"最终归宿"卡片 + 全局统计（总收入、良心值、他们的现状）——严肃向的收尾演出 |

华丽人生2 没有的四样东西（叙事分支结局、日/时段循环、分支对话树、存档），恰好是本作需要自建的部分，以 GL2 的状态机地基为起点实现。

## 三、核心玩法循环（借用 GL2 的 TurnPhase 状态机思路）

**昼夜循环**，一局约 20–40 游戏日（现实 1–2 小时）。DayPhase 状态机仿照 GL2 的 RollAndMove→EventRoll→ActionPhase→结算：

1. **白天·结算**：推进日程 → 掷事件骰查事件表（可重复小事件/一次性剧情事件）→ 收支结算（房租、美颜会员、给家里转账 vs 昨夜红包收入，用 GL2 的 IncomeBreakdown 透明化）
2. **夜晚·分配**：有限精力值 + 2 个聊天时段；打开通讯录选今晚崩谁（老头有活跃时段：司机深夜、退休干部上午错过的只能在留言里补）
3. **聊天会话（核心）**：仿 IM 界面。老头按原型×心情发消息（台词矩阵选取）→ 玩家从 3–5 个话术选项选择（选项带话术标签/三轴效果/人设匹配系数/精力消耗）→ 把握时机发"要红包"（成功率=f(信任段位, 阶段, 他的钱包, 心情)，概率推导写进 constants.ts 注释并由测试断言）
4. **夜结算**：三轴衰减（GL2 的 turn-end settlement 模式）→ 断联惩罚 → 人设穿帮风险累积判定 → 主角精力恢复、麻木值累积

**经济系统**：收入（10–520 元红包阶梯）vs 支出（房租/话术课/美颜会员/给家里转账）；开局动机（负债 3 万/家人生病/逃离小镇）决定目标与难度。

## 四、系统设计

- **老头原型 5–6 个**（M1 先做 1 个）：丧偶退休教师、离异出租车司机、已婚个体老板、"90后"网吧老板、独居老工程师……各有话题（钓鱼/股票/车/游戏/抖音）、情感缺口（没人听他说话/渴望被崇拜/想找女儿的感觉/想证明还有魅力）、警惕阈值、付费习惯（20 元奶茶型/520 冲动型）。每人至少 1 个非收割结局（他其实知道/他想线下见你/被拉黑后彻底孤身）。
- **人设卡 4 张**（M1 先做 1 张 + 匹配系统）：解锁不同话术树与照片类型；换人设有养号成本。
- **主角隐藏属性**：精力（低精力只剩敷衍选项→伤关系）、麻木（表演亲密累积）、良心（关键事件记录）。
- **结局 6–8 个**由（总崩额/良心/麻木/产业化程度/识破数）共同决定：还债收手、被识破身败名裂、被查处（参考现实 3400 万判决案）、成为产业链头目、良心发现补偿……以"账本回顾画廊"演出。

## 五、技术方案（对齐华丽人生2）

Vite + TypeScript(strict) + **React 19 + Zustand**（与 GL2 相同，便于直接移植引擎模式）+ Vitest。零美术/音频资产（程序化 SVG + Web Audio）。目录结构沿用 GL2 惯例：

```
E:\ai_code\OldManBeng
├─ index.html  ├─ package.json  ├─ vite.config.ts  ├─ tsconfig.json
└─ src/
   ├─ main.tsx / App.tsx          # 按 GamePhase 切屏（标题/开局/主界面/结局）
   ├─ types/                       # Target/TargetState/Persona/GameState/Action 全部类型
   ├─ data/                        # 纯数据：targets.ts personas.ts dialogue.ts(原型×场景矩阵)
   │                               #        events.ts scripts.ts(对话树) endings.ts constants 平衡数值
   ├─ engine/                      # 纯函数：state-machine.ts dispatch + chat.ts 要红包判定 + __tests__/
   ├─ store/                       # Zustand 薄封装
   ├─ components/                  # UI：聊天视图/通讯录/人设/账本/HUD/结局画廊/程序化头像(character-art)
   └─ utils/                       # seed RNG / formatMoney / sound / fxQueue
```

## 六、里程碑（M1 为本次实施范围）

1. **M1 垂直可玩切片**：脚手架 + 类型 + 引擎骨架（dispatch/日循环/衰减/存档）+ 聊天会话（选项→三轴→老头回应）+ 要红包判定 + 通讯录 + 精力经济 + **1 个完整老头**（离异出租车司机"老李"：15–20 对话节点覆盖试探→熟络→收割→危机四阶段）+ **1 张人设卡 + 匹配系数** + 程序化老头头像 + Web Audio 消息/红包音效 + 开场内容提示 + balance/simulation/safeguards 三类测试跑通。
