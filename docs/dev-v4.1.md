## 一、总设计原则（所有修复必须服从）

1. **受害者视角优先**：目标玩家是男性玩家，要理解受害者（老头）的处境。一切新增内容
   的第一准绳：让玩家看见"钱是从哪个具体的人的哪件具体的事上来的"，而不是"数值又涨了"。
2. **规则驱动，不接 LLM**：所有内容是手写数据池 + 纋引擎派发。定位如实标注（README 首段
   与 itch 页面均写明"规则驱动对话游戏"）。
3. **不新增大系统**：修复以"复用现有通道 + 新数据"为主（晨报/朋友圈/incoming/档案），避免
   "每个系统都做了但每个都浅"的老路。唯一例外：库目标个性化（见 4.1），它替换的是现有系统
   的数据层，不是新系统。
4. **内容红线继承**：只输出消息文本、一个气泡一行、不旁白、允许冷场、无金融实操细节
   （卡号/验证码/收款渠道）、无未成年暗示。修复不得破坏 115 条测试锁定的既有行为。

## 二、本轮修复清单（按评审编号）

### P0-2 / P0-4 合并修复：主题进玩法层 + 反向使用护栏 ——「代价呈现层」系统化

**现状**（v4.0 已做一部分）：开口要到钱时注入一帧内心旁白（ASK_COST_NARRATOR，Day 8 起）。

**本轮目标**：把"代价"从"开口瞬间的一帧"扩展成**贯穿全过程的呈递系统**，共四个触点：

| # | 触点 | 时机 | 内容 | 落地方式 |
|---|------|------|------|----------|
| 1 | 开口旁白 | 要到钱时（已有） | 她看见的他的代价 | v4.0 ASK_COST_NARRATOR，本轮**扩写**：每个主角 3→6 条，覆盖全部 5 人 + 库目标兜底 |
| 2 | **红包字幕** | 每笔红包入账时 | 红包金额的"来源字幕"：这笔钱在他的世界里是什么钱 | 新增 `PACKET_SOURCE_SUBTITLE`：按主角 × 档位（小额/中额/大额）手写字幕，接在红包系统气泡后 |
| 3 | **主动转账旁白** | runMorning 自发礼物时 | "没人开口要过这笔钱"从日志行升级为**入账旁白**：他的日子当时正在发生什么（人生线节点联动） | 新增 `GIFT_NARRATOR`：与人生线 beat 联动——礼物发生在他的忌日/复查日/家长会日，字幕写他当时的事 |
| 4 | **钱包月度回望** | 每天睡前（sleep 界面） | 当天入账的钱在"他的世界"里的清单：今天你拿的钱，是老李的修理厂欠款，是王总的教育金 | 新增 `MONEY_HOME`：sleep 动作时把当天 packet/gift 流水的 note 转成"来源行"，显示在事件流尾部（不新页面） |

**验收标准**：
- [x] 任意一局第 10 天，一天之内至少出现 2 个不同触点的代价文案（自动化测试）
- [x] 5 个主角的开口旁白池 ≥6 条（数据审计测试）
- [x] 截图任意一条开口话术+旁白，读出的应是"批判"而非"教程"（人工抽检，文案已按此写）

### P0-3 修复：50 人库 = 10 原型 × 5 换皮 ——「库目标个性化」

**根因**：库目标共用 `ARCHETYPE_PACKS[archetype]` 话术组——5 个保安说一模一样的话。

**方案**（深审 P0-3 折中版）：**不写 45 条链，但让每个库目标有"自己的话"**。三层：

1. **个人进场白**（`LIBRARY_OPENERS`）：45 人每人 2 条**只属于他自己的**开场白——
   从他的 bio 里的具体细节长出来（监控室的雷子→"四十块屏幕"话术；北门老翟→"高架吃灰"
   话术）。挂在 `TargetScript.firstOpeners`，start_chat 时如果 `t.chatsCount === 0`
   优先播放，播完进原型组。
   - 实现：新数据文件 `library-openers.ts`（45×2 = 90 条），registry 挂载。
   - 引擎：`start_chat` 里 `chatsCount === 0` 时优先选 firstOpeners（构造一个一次性 pack）。
2. **个人 incoming**（每人 1 条）：他来找你时说的第一句话是他的，不是原型的。挂
   `TargetScript.firstIncoming`，runMorning incoming 选择时 `chatsCount === 0` 优先。
3. **人生线补充（库目标 5 条）**：为 5 个最有戏的库目标各写 1 个人生线节点（毕师傅的
   猫咖/孙老爷子的孙子/老雷的棋摊/宁叔的水边/蒋叔的音响）——他们也要过日子。挂
   `LIFE_EVENTS`，引擎无需改动（LIFE_BY_TARGET 已按 targetId 索引）。

**验收标准**：
- [x] 45 个库目标全部有 ≥2 条个人进场白 + 1 条个人 incoming（数据审计测试）
- [x] 两个同原型库目标（g1 vs g2）的第一次聊天开场白不同（引擎测试）
- [x] 个人进场白与 bio 一致性人工抽检 5 条（g8 监控室/老翟北门/雷子屏幕/孙老爷子/蒋叔音响）

### v4.1.2：话术新鲜感（跨重开随机化）——本轮追加

**问题**（用户实测反馈）：每次重开游戏，同一个老头命中的永远是同一套话术。
30 种子实证定位到两个根因，均已修复：

1. **库人物首聊开场白按"发现日"索引**（`discoveredDay % len`）——同一天遇到他，
   不管什么种子都是同一条。→ 改为 `pickFreshLine`（rng 随机抽 + 跨场去重）。
   修复后 g8 两条个人开场白 30 种子各 ~50%（修复前 30/30 同一条「你好。」）。
2. **主五人前几晚走剧情链是固定剧本**（链节点不耗 RNG、逐字固定）。→ **链夜随机
   穿插**（`CHAIN_INTERLUDE_CHANCE = 0.3`）：30% 的链夜改聊闲聊组，剧情节点
   原地保留到下一晚。**随机的是节奏，不是顺序**——c_li_1 初遇 → c_li_8 开口 →
   c_li_11 坦白的弧序不可乱（乱序会断裂叙事和收获门槛）。实证：穿插率 27.3%
   （≈30%）、首晚 120/120 必推链、10 局乱序 0、闲聊晚零消耗链节点。
   - 首晚保护：本局一个链节点都没消费过 → 不穿插（初遇节点被闲聊顶掉会认知断裂）
   - 确定性分派（seed mod 10，不耗随机流）：同存档同晚重放结果逐字一致，
     且不挤占话术池/开场白的随机流
   - 覆盖两路：start_chat（玩家开聊）与 accept_incoming（他先找你）节奏一致
   - 穿插晚的连锁语义：昨晚闲聊话题今晚可接（recall 门 `!activeChain`）、
     end_chat 清 pendingChain（pickChainNode 从 flags 重推导，弧序无损）
3. 测试迁移：v3 三个单种子链断言（c_li_wise / c_li_8 personaText / c_zhou_art）
   → 多种子扫到模式（60 种子内必中，~70%/种子）。新增 `v412-freshness.test.ts`
   5 条回归：首晚保护 / 节奏方差 ≥3 种 / 顺序保证（穿插零消耗 + 严格保序）/ 
   库首聊两条池现身 / 同存档重放一致。
4. 验证：tsc 零错 / vitest 145 全过 / vite build 通过。
