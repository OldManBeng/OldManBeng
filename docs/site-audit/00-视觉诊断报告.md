## 二、字体使用现状

- 楷体（`--font-kai`）只给叙事文本（log-line / 镜像行 / 经文 / 天数），层级清晰 ✅。
- **问题 F1**：`--c-fs-micro: 11px` 用在了 7+ 处**功能性标签**（关系条
  `comfort-rel-strip`、简报行 label、事件 tag、语音秒数）——低于移动端
  可读下限，11px × 4.9:1 处于 AA 边缘。
- **问题 F2**：字阶 6 档 + 钉死的旧档 `--fs-7/--fs-8`（1928-1930 注释自认
  「未映射」）——别名层有两套口径并存，易漂移。
- 数字已用 `tabular-nums`（语音秒数、钱包）✅，但 HUD 余额之外的
  金额（事件卡 `+5元`、钱包 summary）未统一等宽。

## 三、间距现状

- 4px 网格令牌 `--c-s-1..6` 已建 ✅；但**混用严重**：同一张卡内
  `padding: 8px 6px`（2289-2290，6px 违反网格）、`margin: 0 -10px`（2314）、
  `gap: 10px`（2301）与令牌值并存——10px/6px 均不在 4px 刻度上。
- 卡片体系三种留白并存：event-card 12/16、day-row 10/12、verse 10/12——
  数值接近但来源不同（一半令牌一半裸值）。

## 四、组件现状

- 按钮三档高度（32/44/52）✅、每屏唯一主 CTA ✅、禁用态有专属样式 ✅。
- **问题 C1（违规）**：`comfort-screen.tsx:457` 用了 emoji `📨` 做剧情卡标记——
  **违反全站「不用 emoji」红线**（icons.tsx 注释明示），且 emoji 跨平台渲染不一致。
- **问题 C2**：`muted-btn`（婉拒/晾着他/先不回）与普通 `btn small` 的视觉差
  仅靠全局类，暖主题下没有专属层次——「不回」是有代价的动作，按钮却最不显眼。
- **问题 C3**：语音条 `voice-secs` opacity 0.7 + 11px，白底上对比不足 4.5:1。
- **问题 C4**：事件卡左侧彩条语义不完整——只有 `bf_demand` 有专属红，
  `mom_gift`（温情进账）/`story`（暗线剧情）/`quarrel`（冲突）共用主橙，
  「信」与「钱」在视觉上无区分——与「妈的钱没有来源字幕」的叙事锚点脱节。

## 五、布局现状

- 420px 单列 + 玻璃 HUD/底导航，与工作手机同构 ✅；无横向溢出风险点
  （所有卡 max-width 受容器约束）。
- **问题 L1**：夜间态只染了 day-chip 与 phone-tag 两个元素
  （2245-2246）——覆盖面太薄：夜里的气泡、事件卡、速聊行仍是纯白日样，
  「阿凯只有夜里醒着」这个核心机制在视觉上几乎不可感。
- **问题 L2**：「开始今天」弹窗信息密度高（余额格 + 多行 rule + 经文 +
  事件行），行间全部 10-12px 裸值，缺乏分组呼吸感。

## 六、响应式现状

- `min(420px, 94vw)` 弹窗、`flex-wrap` 按钮组 ✅；语音条 `min-width: 92px`
  + 头像 30px + 长文本在 360px 视口下有轻微挤压风险（低优先级）。
- `prefers-reduced-motion` 已覆盖语音波/翻转/气泡 ✅（本项目的示范项）。
